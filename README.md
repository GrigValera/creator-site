# CREATOR

Одностраничный сайт веб-студии с портфолио, конфигуратором предварительной оценки и формой заявки. Сайт предназначен для ознакомления с услугами и отправки прямого обращения или обращения с расчётом.

Стенд для просмотра — https://creatorstudy.alwaysdata.net/.

## Локальный запуск

Для разработки, тестов и выпуска используйте Node.js 24. На стенде работает эта же версия.

```sh
npm ci
npm run check
npm test
npm run dev
```

`npm run build` создаёт клиентскую сборку в `dist/`, временный серверный бандл в `.ssr/` и предварительно генерирует `dist/index.html`. Оба каталога очищаются перед каждой сборкой. `npm start` обслуживает готовый `dist/` и API на `http://127.0.0.1:4173/` по умолчанию. `npm run preview` проверяет сборку через Vite. В `dev` и `preview` локальная форма без вебхука выдаёт тестовое подтверждение. Внешней отправки в этом режиме нет.

## Структура

| Путь | Назначение |
| --- | --- |
| `src/App.jsx`, `src/pages/home/` | Сборка приложения, композиция главной, отдельные секции и их данные |
| `src/features/estimate/` | Шаги конфигуратора, правила расчёта, бриф и переиспользуемый внутри сценария список вариантов |
| `src/features/inquiry/` | Форма, её состояние, проверка, скачивание брифа и HTTP-клиент доставки |
| `src/shared/layout/`, `src/shared/ui/` | Общие секции, кнопки, ссылки-действия и иконки |
| `src/assets/`, `src/styles/` | Общие ресурсы, глобальные переменные и базовые стили. Стили секций и функций находятся в их CSS Modules |
| `src/main.jsx`, `src/entry-server.jsx` | Входы браузера и предварительного рендера |
| `api/`, `server/` | Точка входа API, отдельный Node.js-сервер, валидация и доставка |
| `scripts/` | Предварительный рендеринг HTML и подготовка выпуска |
| `test/` | Проверки расчёта, брифа, валидации и запроса с подтверждением частичной доставки |

Главная передаёт выбор проекта в конфигуратор, а собранный бриф — в форму. Форма и конфигуратор не импортируют друг друга. Сервер использует отдельные входы в `api/` и `server/` и не зависит от компонентов React.

Черновые кандидаты в портфолио хранятся в самостоятельных репозиториях [«Смена»](https://github.com/GrigValera/smena-ceramics-demo) и [«Релей»](https://github.com/GrigValera/relay-crm-demo). В сборку CREATOR они не входят. Ветка `preview/creator-pages` сохраняет историческую статическую сборку. GitHub Pages для репозитория CREATOR отключён.

## Сборка и выпуск на alwaysdata

Собирайте выпуск из чистой рабочей копии или чистого коммита.

```sh
npm ci
npm run check
npm test
npm run package:alwaysdata
```

Последняя команда заново собирает сайт и создаёт новый каталог `release/alwaysdata-*`. Она печатает его полный путь. Каталог включает HTML, ресурсы из манифеста текущей сборки Vite, `package.json` и рабочие файлы `api/` и `server/`. Для запуска собранного пакета устанавливать npm-зависимости на хостинге не требуется.

1. Загрузите каталог выпуска по SCP в домашнюю папку аккаунта alwaysdata.
2. В **Web → Sites → Configuration** выберите **Type** `Node.js` и **Node.js version** `24`. В **Working directory** укажите относительный путь к новому каталогу. В **Command** укажите `node /home/ИМЯ_АККАУНТА/КАТАЛОГ_ВЫПУСКА/server/start.mjs`.
3. В **Environment** задайте `HOST=::` и серверные параметры доставки. Порт предоставляет хостинг. Сохраните настройки.
4. Откройте сайт, отправьте прямую заявку и заявку с расчётом. Для каждой проверьте фактическое получение в обоих каналах. До проверки сохраните предыдущий выпуск для отката через **Working directory** и **Command**.

У стенда ручное развёртывание. Публикация коммита в GitHub сама не обновляет alwaysdata. Для Vercel предусмотрен `vercel.json` с командой сборки и выходом в `dist/`. Переменные Preview задаются отдельно.

## Форма и API

`POST /api/inquiries` принимает JSON с полями `contact`, `task` и `estimate`. Обязательны контакт и хотя бы описание задачи или расчёт. Форма может отправлять идентификатор и подтверждение частичной доставки для повтора. На Node.js ответ `200` означает подтверждение доставки от настроенных провайдеров или обработчика, `502` означает полный либо частичный сбой отправки, `503` означает, что доставка не настроена.

| Серверная переменная | Назначение |
| --- | --- |
| `CREATOR_RESEND_API_KEY` | Ключ Resend с правом отправки писем |
| `CREATOR_EMAIL_FROM` | Отправитель, доступный в Resend |
| `CREATOR_EMAIL_TO` | Адрес получения заявок |
| `CREATOR_TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `CREATOR_TELEGRAM_CHAT_ID` | Числовой ID чата с доступом для бота |

При прямой доставке сначала заявку принимает Resend, затем Telegram. При частичном успехе форма может повторить только Telegram с подписанным подтверждением в течение 24 часов. Если Telegram принял сообщение, а его ответ потерялся, повтор может создать дубль. Собственной базы заявок нет.

Вместо прямой доставки можно задать серверный `CREATOR_INQUIRY_WEBHOOK`. Он имеет приоритет и должен указывать на HTTPS-приёмник. Для отдельного статического фронтенда можно указать адрес обработчика через `VITE_INQUIRY_ENDPOINT` и настроить CORS на стороне обработчика. Переменные с секретами задаются только на сервере.
